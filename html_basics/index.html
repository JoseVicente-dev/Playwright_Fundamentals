HTML Fundamentals: Tags, Attributes & Classes

1. Anatomy of an HTML Element

An HTML element is made of an opening tag, optional attributes (name-value pairs), the content, and a closing tag:

<button id="submit-btn" class="btn btn-primary" type="submit">Submit Order</button>
  • Tag Name: button — Specifies what type of element this is.
  • Attribute Name: id, class, type — Extra settings or metadata on the element.
  • Attribute Value: "submit-btn", "btn btn-primary", "submit" — Always wrapped in quotes.
  • Content: Submit Order — The text or inner HTML between opening and closing tags.

2. id vs class

Feature id Attribute class Attribute
Uniqueness Must be unique in the entire document (only 1 element can have id="login-btn"). Can be reused on dozens or hundreds of elements across the page.
Number of values Only one single word/token (no spaces allowed). Multiple values allowed, separated by spaces: class="btn btn-primary active".
CSS Selector #submit-btn (prefixed with #) .btn or .btn-primary (prefixed with .)
Playwright Locator page.locator('#submit-btn') page.locator('.btn.btn-primary')
Real-World Analogy Like a Passport number or SSN (identifies one exact person). Like clothing (many people can wear a "blue-shirt" and "sneakers").

4. Plain Text & DOM Hierarchy (Parent, Children, Siblings)

A. Plain Text (Text Nodes)

In HTML, text is not an element tag; it is represented in the DOM as a distinct Text Node:

<div class="greeting">
  Welcome back, <strong>Alex</strong>!
</div>

Inside this single <div>, there are 3 distinct nodes:
1. Text Node: "Welcome back, "
2. Element Node: <strong>Alex</strong> (which wraps its own Text Node: "Alex")
3. Text Node: "!"

B. The DOM Family Tree (Parent, Child, Sibling)

Every HTML document is arranged as a hierarchy of nodes:

┌── <div class="card">                           ◀── PARENT NODE
│   ├── <h3>Wireless Mouse</h3>                  ◀── CHILD (Sibling to <p> and <button>)
│   ├── <p>Ergonomic silent mouse.</p>             ◀── CHILD (Sibling to <h3> and <button>)
│   └── <button class="buy-btn">Buy Now</button>   ◀── CHILD (Sibling to <h3> and <p>)
└── </div>
Relationship Definition Playwright Automation Usage
Parent Node The immediate container element directly enclosing another element. Locator Chaining: page.locator('.card').getByRole('button') scopes search inside parent.
Child Node Any element directly nested inside a parent element. Filtering by Child: page.locator('.card').filter({ hasText: 'Wireless Mouse' }).
Sibling Node Elements that share the exact same immediate parent. Finding a sibling relative to another sibling: page.locator('h3 + p') or filtering their parent.

4. How Frameworks Handle Classes (React, Vue, Angular)

A. React (JSX) → className

In JavaScript, class is a reserved keyword used for creating ES6 classes (e.g. class Car {}). Because JSX is transpiled directly into JavaScript calls (React.createElement), React uses className instead of class:

// React JSX:
<button className="btn btn-primary">Save</button>

// Dynamic in React (Template literals):
<button className={`btn ${isActive ? 'is-active' : ''}`}>Save</button>

B. Vue.js → :class / v-bind:class

Vue templates allow normal class for static styles, plus :class for dynamic bindings using objects or arrays:

<!-- Vue template: merges static and dynamic classes automatically -->
<button class="btn" :class="{ 'btn-success': isSaved, 'is-loading': isLoading }">Save</button>

C. Angular → [class] / [ngClass]

Angular uses square brackets [ ] for property bindings:

<!-- Angular template: single class toggle or ngClass object -->
<button class="btn" [class.is-active]="isActive">Save</button>
<button [ngClass]="{ 'btn-primary': isPrimary, 'btn-large': isLarge }">Save</button>

💡 What does Playwright see?

Playwright only sees the final rendered HTML in the browser DOM! Regardless of whether a site was written in React, Vue, or Angular, the browser DOM always outputs:

<button id="demo-button" class="btn btn-primary is-active">Save</button>

So in your Playwright tests, you always locate by standard classes (e.g. page.locator('.btn.is-active')), never by className or :class.
